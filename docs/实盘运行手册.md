### 为什么 2 万两条只做纸面追踪

不是因为它们回测难看，而是因为**结果不可信**。同一份预测扫 3 档本金 × 5 种只数：

| 本金＼只数 | 2只 | 3只 | 4只 | 5只 | 6只 | 跨只数标准差 |
|---|---|---|---|---|---|---|
| 2万 | 1.33 | 0.62 | 1.14 | 0.11 | 0.17 | **0.55** |
| 5万 | 0.82 | 1.58 | 1.45 | 1.51 | 1.53 | 0.32 |
| 10万 | 0.83 | 1.61 | 1.52 | 1.42 | 1.56 | 0.32 |

（表内为 IR）5 万和 10 万两行**几乎完全重合**，互相印证；2 万那行毫无规律。
根因是 A 股 100 股最小单位：6,667 元一个槽位买不起多少股票，
买不起就沿排名往下换，组合被搞得面目全非（`steady2w` 全程发生 157 次）。

> **别拿 2 万那行的任何单个数字做决策。** 比如「2万/2只 IR 1.33 最高」是离群值 ——
> 同样的 2 只在 5万/10万 两次独立验证里都是**最差**的（0.82、0.83）。

### 两条基准线的意义

前四条给了四个不同的人用，会被改名、切手工记账、校准现金、删持仓。跑一段时间后
就无从分辨「赚亏是策略本身的还是人为干预的」。所以加两条**锁死**的参照线，
参数与 `steady5w`/`aggr5w` 逐字相同。

**真实账户 − 对应基准线 = 人为干预的代价。**

锁的范围（后端返回 403，不是只把按钮藏起来 —— 藏起来的按钮 curl 一样打得到）：

| 操作 | 基准线 |
|---|---|
| 改名 | 拒 |
| 切记账方式（纸面/实盘） | 拒，恒为纸面自动 |
| 确认成交 | 拒 |
| 校准现金 | 拒 |
| 存取现金 | 拒 |
| 删持仓 | 拒 |

判定入口只有 `live_config.is_locked()` 一处。要加新的基准线，在 `PROFILES` 里
加 `"locked": True`，前后端自动跟上。

## 2. 每天自动干什么

systemd 定时器 `quant-daily.timer`，**周一到周五 17:30 / 19:30 / 21:30**（香港时间）
各跑一次 `daily_rebuild.py --full-market`。跑三次是因为行情数据到位时间不稳定，
早的那次常因数据未更新而跳过，后面的补上。

```
拉全市场日线K线(约 25 分钟，网络瓶颈)
  → 构建特征
  → 训练模型 + 出预测       ← 一天只训一次，六条线共用
  → 逐条线结算昨天的挂单 + 出今天的新计划
```

**幂等**：若 K 线最新日没超过训练集最新日，判定为非交易日或数据未更新，直接跳过，
不会重复记账。今晚 19:30 那次就是这样跳过的。

### CPU

一天训 **1 个**模型（全部历史从零重训，约 15 秒 / 2~3 核）。六条线共用一份
预测缓存 `data/live/preds_cache.json` —— 模型只依赖特征/标签/训练集，
不依赖本金和只数，所以各训一遍纯属浪费。

缓存键含信号日与全部训练输入，任一项变化自动重训，**不会读到过期预测**。
删掉缓存文件只会导致下次多训一遍，无副作用。

> 别把这个 15 秒和「完整回测」搞混。回测要按 walk-forward 逐日训 **688 个**模型
> （约 1.5 小时 / 10 核），只在换特征或换标签时才需要跑。日常不需要。

### 查看

```bash

journalctl --user -u quant-daily.service -n 100     # 上次跑了什么
```

## 3. 纸面模式 vs 实盘模式

每条线（除基准线）可独立切换。

| | 纸面（`auto=true`，默认） | 实盘（`auto=false`） |
|---|---|---|
| 记账 | 每天按 T+1 真实行情自动记 | **不自动记**，等你填真实成交价 |
| 不填会怎样 | — | 这条线停在「待确认成交」，**不再往前推进、不出新信号** |

实盘模式下管线跑到确认闸门就停住，**不会覆盖你的计划**。

切到实盘模式时，若已有挂单计划，那份计划会转为「待确认」—— 因为系统无法知道
你到底有没有按它下单。

### 手填的数字不会被刷新洗掉

页面 60 秒自动刷新一次。填过的股数/成交价会持久化（按 条线+信号日 隔离），
且**一旦动过手就暂停自动刷新**，提交成功后一起清掉。

## 4. 三种改账操作，别用错

这三个语义完全不同，用错会把账搞坏。

| 操作 | 改什么 | 收益率 | 什么时候用 |
|---|---|---|---|
| **校准现金** | 只改现金，本金不动 | **被修正到真实水平** | 消除自动记账（收盘价+估算佣金）的累积偏差 |
| **存取现金** | 现金和本金**同额**增减 | **不变** | 真的往账户里存钱/取钱 |
| **删持仓** | 见下 | — | 系统记的持仓和券商不一致 |

**存取现金为什么要同时改本金**：否则存进 1 万会被算成「赚了 1 万」。
但注意收益**百分比会被稀释**（分母变大），做过出入金后请看「累计盈亏」的金额，
别看百分比。

**删持仓的两种情形现金处理正好相反**，所以必须显式选，后端不猜：

- `已卖出` —— 钱回到账户了，需填真实卖出价，现金增加
- `记错了` —— 本就没这笔，只删记录，现金不动

## 5. 关键不变量（改代码前必读）

1. **`hold-days` 必须是 5**，与回测的 `--hold-days` 一致。
   `wf_v35` 默认 5，而 `live_signal.py` 的 argparse 默认是 **10** —— 历史上线上
   跑的是 10，与所有回测结论口径不符。所以 `live_config.BASE_PARAMS` 里显式钉死 5。
   持有期必须等于标签 horizon（标签是 5 日）。

2. **股票池锁定 497 只 PIT 自选股**。扩到 2303 只会彻底失效
   （总收益 −67.4%、夏普 −1.01、IR −1.59）。

3. **特征复用回测锁定的列表**，不现场筛选，保证与回测完全一致：
   `FEATURES_FROM = wf_daily_REGRESS_CHK_...json`（80 个）。
   必须是用修复后的 `drop_market_wide` 跑出来的结果，否则会带入市场级泄漏特征。

4. **`regime-filter` 关闭**。breadth 择时在当前配置下有害
   （5万/3只：off +292% IR 1.37 vs breadth +51% IR 0.34）。
   早期 hold=10 时 breadth 看似有效，是因为它在补救一个本身就坏的基线。

5. **参数只能改 `live_config.py` 一处**。`daily_rebuild` / `web_server` / 命令行
   三处都从 `signal_args()` 取。一旦不一致，`live_signal` 的指纹校验会直接报错退出，
   而这发生在收盘后无人值守的时段，不容易发现。

6. **状态文件只由 `live_signal.py` 单方写入**。网页要改的东西（显示名、记账开关）
   另存 `data/live/profile_settings.json`，否则会和定时任务撞车、造成账目错位。

7. **改动 `FINGERPRINT_KEYS` 里的任何参数都会使已有持仓失效**，必须 `--init` 重置。
   `--require-confirm` 和 `--preds-cache` 故意不在指纹里，所以来回切换安全。

## 6. 常见操作

### 看各线现状

```bash
ssh eez041.ece.ust.hk && cd ~/quant-strategy
.venv/bin/python scripts/live_config.py            # 参数总览
.venv/bin/python scripts/init_profiles.py --list   # 持仓与现金
.venv/bin/python scripts/init_baseline.py --list   # 基准线是否仍与参照线一致
```

### 建立 / 重置某条线

```bash
# 建立（已存在则跳过，不会误伤真实账户）
.venv/bin/python scripts/init_profiles.py --profile steady5w

# 重置（清空持仓，旧状态自动备份到 data/live/archive/）
.venv/bin/python scripts/init_profiles.py --profile steady5w --force
```

### 让基准线重新对齐参照线

```bash
.venv/bin/python scripts/init_baseline.py --force
```

它**复制参照线当前的状态与挂单计划**，不是从满现金另起 —— 后者会比参照线晚一个
换仓周期建仓、入场价也不同，前期差额全是「起点不同」的噪声，而非人为干预的代价。

脚本会先检查参照线是否干净：**有实质人为干预（delta 非 0）就拒绝复制**，
否则等于把污染搬进基准线。

### 手动补跑管线

```bash
.venv/bin/python -u scripts/daily_rebuild.py --full-market
```

### 重启网页

```bash
systemctl --user restart quant-web.service
systemctl --user is-active quant-web.service
```

## 7. 出问题怎么查

| 症状 | 先看哪里 |
|---|---|
| 页面显示的计划是旧的 | `pipeline_status.json` 的 `skipped_reason`；页面本身会对数据不新鲜显式报警 |
| 某条线不出新信号 | 是不是实盘模式且停在「待确认成交」 |
| 指纹校验报错退出 | 有人改了 `live_config.py` 的指纹参数但没 `--init` |
| 网页 503 | `QUANT_OPS_PASSWORD` 没设，改账接口被主动禁用 |
| 基准线和参照线分歧了 | 正常，说明参照线被人动过 —— 这正是要测量的东西 |
| 基准线自己被改了 | 不可能，六个写接口都返回 403。若真发生说明 `is_locked` 被绕过了 |

日志：

```bash
journalctl --user -u quant-daily.service -n 200 --no-pager
journalctl --user -u quant-web.service -n 100 --no-pager
```

## 8. 还没做的事

1. **2 万本金的整手粒度问题**。现在买不起一手就跳到排名更差的股票。
   可能的解法是允许槽位预算浮动（宁可超配一点也买排名最高的），用等权纪律换
   信号保真度。**未验证**，有自己的过拟合风险，需单独 A/B。

2. **回测加速**（仅在需要重训时才有意义）。非换仓日的预测除了算 IC 统计外
   并未用于交易，理论上 688 个模型可降到 138 个（1.5 小时 → 约 20 分钟）。
   两个坑：`is_rebal` 与到期时钟都靠逐日下标算，不能少排期；且 IC 的 t 值
   会因样本砍到 1/5 而明显变弱 —— 而 IC 显著性是唯一能证伪策略的统计量。

3. **IC 显著性本身仍是隐忧**。见 `findings_2026-07-29_capital_constraint.md` §6：
   只持 3~5 只的组合，总收益的 t 值只有约 1，统计上无法与 0 区分。
   **评价策略应看 IC 及其 t 值，而不是总收益。**
